Find out which attacks your defenses actually stop

Project Achilles is a purple team platform for continuous security validation. It runs safe, real-world attack techniques on your own endpoints, every day, and shows which ones your EDR blocked, which it only saw, and which went through unnoticed.

  • About 80 tests mapped to MITRE ATT&CK: ransomware chains, credential theft, EDR tampering, CIS hardening checks
  • A small Go agent on Windows, Linux and macOS that only calls out over HTTPS
  • EDR evidence pulled from Microsoft Defender, CrowdStrike, SentinelOne and Sophos and matched to each test

    Chapter 1

    Security controls drift. An annual pentest sees one day of the year.

    An EDR policy gets switched to detect-only during an outage. Someone adds a broad folder exclusion to fix a slow application. A new ransomware crew starts using a driver your sensor has never seen. Nothing announces these changes, so the coverage you assume and the coverage you have slowly move apart.

    The gap is invisible without testing

    The shaded area is risk nobody signed off on. Dashboards that count installed agents or enabled policies stay green the whole time.

    Point-in-time is out of date by Monday

    A pentest report describes the environment on the day it ran. Continuous validation re-runs the same techniques on a schedule and catches the drift within a day.

    Measure outcomes, not configuration

    Achilles asks one question per technique and host: did it get stopped, did the SOC see it, or did it run clean?

      Chapter 4

      The agent: small, outbound-only, careful about updates

      A single static Go binary runs as a system service. It never listens on a port. It asks the console for work, runs it, and reports back.

      Enroll once, then poll

      An installer uses a one-time enrollment token. After that the agent sends heartbeats and asks for tasks over HTTPS with its own hashed API key, so it works behind NAT and strict firewalls.

      Runs only signed, verified tests

      Test binaries are Authenticode-signed on Windows and ad-hoc signed on macOS. The agent checks the SHA-256 before it runs anything, inside a work folder locked to SYSTEM and Administrators.

      Updates without bricking the fleet

      A new version must report the version it was registered as. After swapping the binary the agent launches it once to check, and rolls back to the old one if that check fails.

      Watched by the console

      Missed heartbeats mark an agent offline. A task that never reports back is timed out, and if an EDR killed the agent mid-test, the console can prove that from the EDR's own alert.

      Chapter 5
      
      Five verdicts, in order of strength
      
      
      The exit code says what happened on the endpoint. EDR alerts say what the SOC saw. Achilles combines both and keeps the strongest result, so every run lands on exactly one verdict.
      
    
      
    
      
      
      
        
      Protected
      A stage was blocked on the endpoint (exit 105, 126 or 127). The attack did not finish.
      
        
      Prevented
      An EDR confirms it killed, quarantined or blocked the test itself, as part of its own immediate response.
      
        
      Detected
      The technique ran, but an EDR raised an alert that matches this exact run. The SOC would have seen it.
      
        
      Unprotected
      A stage ran unblocked (exit 101) and no EDR alert matched. A real attacker would have succeeded quietly.
      
        
      Error
      The test could not reach a conclusion: a timeout, a missing prerequisite, an agent that went offline. It is reported but never scored.
      
      
      
      
      
        
      
          
      Why Detected is not the same as Protected
      
          
      A detection gives an analyst a chance to respond, which still beats silence. But it depends on someone acting in time. The Defense Score counts blocked and EDR-confirmed results together, and a stricter blocked-only score sits next to it so the difference stays visible.
      
        
      
        
      
          
      Multi-stage tests are judged stage by stage
      
          
      In a five-stage chain, each stage has its own exit code and its own ATT&CK technique. A technique is never marked as covered because a sibling stage was blocked, and the chain-depth view shows how far each chain got before something stopped it.
      
        
      
        
      
          
      Blocked before launch still counts
      
          
      When an EDR's static or machine-learning engine blocks the test orchestrator before it starts, and the EDR's alert names that exact run, the result is rewritten from "not run" to Protected.

      Scored on your current state
      The default view keeps only the latest conclusive result for each test and host pair. Fixing a gap shows up as soon as the test re-runs, instead of being diluted by months of old failures.
      
      
      Accepted risk stays honest
      When the business accepts a gap on purpose, you can exclude it from the headline score. The original series is kept alongside, so the decision is visible rather than hidden.

      Same host, same window, same lineage
      An alert is linked when it is on the test's host, inside the run's time window, and its parent or grandparent process is the test. Loose matches on file names are not enough.
      
        
      The SOC queue stays clean
      Once an alert is proven to be a test, Achilles can close it in the EDR console with a note naming the run. Dry-run mode shows what it would close before you let it write anything. The test results themselves are never edited.
      
        
      The EDR's own posture, scored alongside
      Microsoft Secure Score, CrowdStrike Zero Trust, and Achilles-computed scores for SentinelOne and Sophos are trended next to the Defense Score. Posture checks also flag exclusions that would quietly whitelist every test.

      The same results answer two kinds of questions: "what should we tune this week?" and "how exposed are we, and is it getting better?"
      
    
      
    
      
      
      
        
      For security operations
      
        
        
          
      • A detection backlog ranked by evidenceEvery Unprotected technique is a concrete detection gap, with the exact host, binary and time to reproduce it.
        • 
          
      • Proof that a fix workedChange a policy, re-run the test, and watch the verdict change the same day. No ticket gets closed on assumption.
        • 
          
      • Regressions caught earlyA sensor update, a new exclusion or a policy rollback shows up as a score drop, with Slack or email alerts when it crosses a threshold.
        • 
          
      • Purple teaming without a scheduling meetingPre-execution notices tell the SOC what will run and when, so red activity is expected and blue response can be observed.

        •

      Chapter 9
      
      Guardrails for running attacks in production
      
      
      Running offensive techniques on real endpoints only works if the platform is safe to operate. These protections are built in.
      
    
      
    
      
      
      Announced before it runs
      With pre-execution notices on, tests are held on the server until the email is accepted for every recipient, plus a lead time you choose. A broken mail server holds the tests rather than letting them run unannounced.
      
      
      Signed and hash-checked
      Every binary is signed with your own certificate and verified by SHA-256 before it runs. Posture checks warn if an EDR trusts that certificate, which would whitelist every test.
      
      
      Roles and organizations
      Viewers, operators and admins get different permissions. Organizations are isolated from one another, and shared EDR settings become read-only in multi-tenant installs.
      
      
      Scoped API keys
      Automation keys come in read, read-write and admin scopes. No key can create users or more keys, so revoking a leaked key contains the incident.
      
      
      Safe self-updates
      Version checks, a launch test at the final path, automatic rollback and a repeat-install guard keep a bad build from knocking the fleet offline.
      
      
      Deployed where you need it
      Docker Compose, a single server behind Caddy with automatic TLS, an on-prem LAN installer with its own constrained CA, or managed cloud hosts.
